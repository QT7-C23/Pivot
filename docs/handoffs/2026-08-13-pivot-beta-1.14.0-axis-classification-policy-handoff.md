# Pivot Beta-1.14.0 Axis classification policy handoff

Date: 2026-08-13  
Display version: `Beta-1.14.0`  
Package version: `1.14.0-beta`

## Delivered engineering slice

- Separated model-owned `AxisClassificationProposal` and `TaskDagProposal`
  from code-owned `ComplexityReport`, `AxisTask`, and `TaskDag` contracts.
- Added confidence, observed repository-risk evidence, score floors,
  low-confidence single-worker fallback, required human review and required
  Gate selection in the Main-only classification policy.
- Bound the final classification Gate/review decision to every authoritative
  task during decomposition. The planning model cannot select or weaken it.
- Guarded Safe Write now checks `task.requiredGates` before permission, Lease,
  Fingerprint, Checkpoint, execution authority or mutation. Unsupported Gates
  fail closed.
- Added benchmark, structural, runtime-contract and real failure-path coverage.
  The failure path proves that an unavailable Security Gate blocks before the
  permission collector is invoked.

## Engineering facts verified

- Full suite: 261 test files, 958 tests passed.
- TypeScript and formal Electron production build passed.
- Performance gate passed: 1.74 MiB initial Renderer, 22.91 MiB total.
- `better-sqlite3` matches both Node and Electron native runtimes.
- No installer or portable package was generated.

## Important limits

- Production Guarded Safe Write currently composes compile and test commands.
  A task requiring correctness or security therefore fails closed; no fallback
  silently weakens the classification.
- Project-specific trusted Gate Profiles, concrete correctness/security Gate
  adapters, layered model routing, circuit breaking and adaptive worker counts
  remain unimplemented.
- This is an Axis foundation improvement, not a newly user-visible autonomous
  workflow and not completion of the v2.0 ecosystem scope.

## Suggested next slice

Build a trusted per-project Gate Profile Port and Main Adapter. Start with
strict profile discovery/validation and execution-capability tests, then compose
concrete correctness/security commands without accepting command text from the
model, Renderer, Worker or project-untrusted files.
