## 1. Delivered engineering slice

Beta-0.1.51 connects only a durably decided Dynamic Pivot `retry` outcome to one task-scoped optimistic Run-state transition.

1. Shared request input remains limited to decision, expected revision, Run and Session identifiers.
2. Task identity comes only from the unforced decided record and its latest matching `pivot-decided` lifecycle event.
3. `AxisPivotRetryStatePort` exposes Session-owned read plus one exact retry mutation and is frozen at construction.
4. The pure transition requires a failed Run and failed target task, with no active sibling.
5. Retry, token, cost, duration and Gate-cycle budgets are rechecked immediately before state mutation.
6. The transition preserves sibling task state and all measured usage, clears only the failed task error, returns that task to `pending`, increments retry usage once, changes the Run to `running`, and records `pivot-retry-scheduled`.
7. Sequential duplicate delivery, a concurrent optimistic-revision conflict, and database close/reopen reuse the same durable event without another revision or retry charge.
8. Any concurrent state that is not the exact same completed decision remains an error.

Worker and Renderer receive no Admin Port, Registry, database handle, task selector, project root, filesystem, command or execution authority.

## 2. Explicit non-delivery

- The handler is not constructed by production composition.
- No IPC, preload, Renderer store or UI calls it.
- No scheduler or Worker consumes the pending task.
- No Lease, Fingerprint, Checkpoint, permission or safe-write authority is issued.
- Retrying a completed task is intentionally rejected because safe redo requires DAG-aware downstream invalidation.
- Self-repair, dedicated Fixer, discard, stop and escalation action boundaries remain absent.

## 3. Tests added or strengthened
