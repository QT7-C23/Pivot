# Pivot 0.1.41 Production Identity 与 Cleanup Lifecycle 交接

## 本轮完成

- 生产 Main composition root 使用同一数据库路径构造 Binding Store、File Identity Adapter、Lease Store 与生命周期协调器；
- startup 为所有 live Session 执行 bind/verify，`IpcRuntimeResources.ready` 成功后才标记 runtime ready；
- create/open/fork 在 IPC 成功前完成 Session binding；
- soft delete 在提交关闭前执行 Session cleanup，并保留 binding 供 undo；
- hard delete 按 cleanup → 既有删除级联 → unbind 顺序执行；
- `axis:cancel-run` 与 Dry-run Coordinator 统一使用 `AxisLeaseAwareRunStateStore`；
- completed/cancelled/failed 先持久提交 Run 终态，再调用 Run cleanup；
- cleanup 失败直接传播，持久终态保留，Lease 由 TTL 兜底恢复；
- shutdown 清理 live Session Leases 并关闭新增 SQLite adapters；
- Worker/Renderer 未获得 Binding Admin、Lease Admin、数据库句柄或文件系统能力；
- 未增加真实写 IPC，也未构造生产 Guarded Safe Write。

## 测试纪律

- 新增测试先因缺少生命周期服务和生产接线而失败；
- 实现后定向 5 个测试文件、21 项通过；
- 全量 125 个测试文件、498 项测试全部通过；
- TypeScript `tsc --noEmit` 通过；
- Electron production build 通过；
- 性能预算通过：12 个 JS chunks；最大 Worker 11.53 MiB；最大 App chunk 4.18 MiB；初始 Renderer 1.70 MiB；总计 22.23 MiB；
- `better-sqlite3` Node/Electron 原生绑定验证通过。

## 真实失败与恢复证据

- cleanup Port 抛错时，Session delete/unbind 不执行；
- Run Registry 已提交 cancelled/failed 后，Lease cleanup 抛错会向调用方暴露；
- 关闭真实 Lease SQLite 连接可复现 cleanup interruption；
- 重启打开 Lease Store 并推进时钟后，active Lease 按 TTL 转为 expired；
- 重启打开 Binding Store 并初始化同一 Session，稳定 `projectId` 不变。

## 尚未完成

- `AxisGuardedSafeWriteHarness` 尚未由生产 Main 构造；
- Typed Blackboard 尚未进入生产 Worker/Checkpoint 主链；
- 没有新的 Renderer/Preload/IPC 真实写合同；
- 没有用户可达的外部修改、回滚和恢复 E2E；
- public Session record 尚不暴露 `projectId`；
- 无后台 Lease heartbeat；
- 未生成安装包或便携包。

不得把 0.1.41 描述为已经交付生产安全写入或用户可达真实 Worker。

## 下一步

独立复审后，先构建 feature-gated 的 production-only Guarded Safe Write runtime factory，接入既有 guarded coordinator、Blackboard evidence 与 recovery，但仍不公开写 IPC。再经过单独评审，新增用户可达合同和外部修改/回滚真实 E2E。

按当前小切片节奏，距离 v1.0 internal beta 约还需 12–19 个独立工程切片；该范围包含集成、恢复/E2E、RC hardening 与发布演练，不是日期承诺。
