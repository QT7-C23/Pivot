# Pivot Beta-0.1.62 guarded continuation consumer handoff

Date: 2026-08-01  
Visible version: `Beta-0.1.62`  
Package/updater SemVer: `0.1.62-beta`

## Completed slice

- Added strict shared contracts for an explicit Pivot handoff binding around
  the existing Guarded Safe Write submission and for durable continuation
  attempt evidence.
- Added narrow Main authorization, Guarded submission and optimistic attempt
  Ports. Consumers do not receive concrete registries, Admin services,
  database handles, Permission, Fingerprint or filesystem capabilities.
- Added a Main-owned consumer that revalidates the durable handoff and
  committed dispatch before accepting reviewed work.
- Supported committed task-scoped `retry` and child-Run `replan`; rejected
  forged ownership, wrong retry Tasks and assignment-only self-repair/Fixer
  evidence before Guarded submission.
- Added a WAL SQLite attempt registry with optimistic revisions, unique
  `(handoffId, requestSha256)` ownership and explicit creator/reuser results.
- Reused completed attempts without replay, kept failed attempts closed and
  changed interrupted `submitting` attempts to `recovery-required` on startup.
- Composed the runtime only when both the default-off production Dynamic
  Pivot and real Guarded runtimes expose their narrow Ports.
- Added readiness recovery, Session cleanup and idempotent shutdown ownership
  to the application composition root.

## Failure-path evidence

- A consumer test invokes the real `AxisGuardedSafeWriteSubmissionService`
  with a stale Run revision.
- The service fails at authoritative Task claim before its execution Port is
  called.
- The consumer persists a failed attempt and rejects the same reviewed
  request on duplicate delivery without calling Guarded again.
- A real SQLite close/reopen converts ambiguous `submitting` evidence into
  `recovery-required`; readiness never replays it.

## Invariants preserved

- Pivot failure evidence, decisions and handoffs never manufacture writes,
  reviewed-proposal Receipts or execution authority.
- The existing Guarded submission service remains the sole verifier of the
  reviewed Receipt, current fingerprint baseline, authoritative Task and
  Project Binding before execution.
- Worker and Renderer receive no new Port, database handle, signing secret or
  filesystem capability.
- No Pivot IPC, Preload contract or Renderer surface was added.
- No installer or portable package was generated.

## Deliberately absent

- automatic reviewed-proposal generation or approval;
- a production orchestration trigger that calls the consumer;
- self-repair/Fixer authoritative Task scheduling;
- non-Dry-run production failure observation;
- restart reconciliation UI or automatic retry of ambiguous attempts;
- Guarded completion/failure history projection;
- stop-driven external process interruption;
- Human Escalation notification, queue, acknowledgement or resolution;
- Pivot IPC, Preload, Renderer or UI reachability.

## Next recommended slice

Add a Main-owned reviewed-proposal producer/orchestrator for durable
`pending-guarded-review` handoffs. It must create or obtain the explicit
proposal and Main-issued Receipt, then call only the new consumer Port. Keep
self-repair and dedicated-Fixer out until a separate authoritative Task
scheduling transition exists. Add production-system tests proving stale
review, duplicate delivery and restart ambiguity remain fail-closed.
