## Delivered engineering slice

Beta-0.1.47 adds a strict, default-off model-produced full-content proposal before the existing Guarded Safe Write approval:

- Main resolves the authoritative Run, pending task and persistent Project Binding;
- the task must request exactly `fs.safeWrite` and the proposal must cover exactly its assigned files;
- a read-only filesystem adapter captures bounded existing/missing source snapshots beneath the bound root;
- a proposal-only model Port receives no tools or mutation capability;
- strict shared schemas reject roots, commands, authority, proof material, extra paths and unknown fields;
- Renderer shows a lazy read-only Diff Review and pre-fills the existing editable approval form;
- explicit user acknowledgement and Main-owned permission approval remain mandatory.

This is review data over the bottom-layer execution path. It is not autonomous execution.

## Budget and failure ordering

Proposal model token/cost/time usage is committed atomically to the authoritative Run state. Later malformed or incomplete model output still retains measured usage. If any hard budget is exceeded, the task and Run durably fail with `safe-write-proposal-stopped`.

Source snapshots fail before model generation when one file exceeds 1 MiB or aggregate source content exceeds 4 MiB. The real adapter checks the actual read byte length after `stat` as well, closing the file-growth race window.

## Capability boundaries

- Shared contracts contain immutable values and strict runtime validation only.
- `AxisSafeWriteProposalService` depends on narrow Reader/Model/Run-state Ports.
- Only Main constructs the filesystem and provider adapters.
- The model cannot invoke tools.
- Renderer and Worker receive no Admin Port, Registry, database handle, Project Binding root, provider secret, proof secret or raw filesystem capability.
- Structural tests enforce the new boundary.

## Real Electron evidence

The production-build E2E:

1. enables the guarded feature explicitly;
2. creates an isolated project and Shadow Run through a local OpenAI-compatible endpoint;
3. generates a model proposal;
4. reaches the read-only Diff Review and verifies the full-content form was pre-filled;
5. requires explicit acknowledgement and Main-owned permission approval;
6. triggers a deterministic TypeScript compile-Gate failure;
7. verifies that the original physical file is restored.

## Honest remaining gap

The proposal contains review-time source hashes, but they are not yet a Main-signed/persisted execution receipt. The later manual submission carries edited content and the current Run revision only. External changes between proposal review and the subsequent Lease/Fingerprint capture can therefore make the displayed diff stale.

Do not describe Beta-0.1.47 as review-baseline-bound or autonomous safe write. The next critical slice should:

1. issue a Main-owned reviewed-proposal receipt;
2. bind proposal ID, authoritative revision, exact proposed content and original source fingerprint;
3. require and verify that receipt before task claim/Lease acquisition;
4. fail closed on stale or changed review baselines;
5. add a successful guarded completion E2E and evidence projection.
