# Pivot Beta-0.1.63 reviewed continuation orchestration handoff

Date: 2026-08-02  
Visible version: `Beta-0.1.63`  
Package/updater SemVer: `0.1.63-beta`

## Completed slice

- Added strict shared request and orchestration contracts for a retry-only
  reviewed-proposal workflow.
- Added narrow proposal, guarded-consumer and optimistic attempt Ports. The
  orchestrator has no concrete Registry, database, Admin, Permission,
  Lease/Fingerprint or filesystem capability.
- Added a WAL SQLite registry with unique decision ownership, optimistic
  transitions and durable `preparing`, `submitting`, `completed`, `failed`
  and `recovery-required` states.
- Persisted `preparing` before proposal generation and `submitting` plus the
  validated proposal result before calling the existing guarded consumer.
- Required an exact committed retry handoff, decision-owned Task and exact
  next-revision proposal result.
- Reused the existing Main proposal service through its narrow Port and
  connected only registered authoritative Dry-run `retry` dispatches.
- Added readiness recovery, Session hard-delete cleanup and idempotent close
  ownership to the Main composition root.

## Real behavior and failure evidence

- The registered Main system test now drives a real failed Dry-run Task
  through Worker-attempt evidence, Pivot decision/dispatch, retry scheduling,
  model proposal generation, Main-issued reviewed Receipt, permission allow,
  Guarded execution, physical file update and completed Run/Task state.
- A real `AxisSafeWriteProposalService` stale-revision failure persists a
  failed orchestration and never calls the continuation consumer.
- A valid but skipped-revision proposal Port result is rejected before
  submission.
- SQLite close/reopen converts both ambiguous preparation/submission work to
  `recovery-required` and never replays proposal or Guarded work.
- Completed duplicate delivery returns the persisted result without another
  proposal or filesystem mutation.

## Invariants preserved

- Pivot evidence does not manufacture writes, Receipt, Permission or
  execution authority.
- The existing proposal service remains responsible for authoritative Task,
  file baseline, model-output and Main-issued Receipt validation.
- The existing guarded consumer/submission service remains responsible for
  current ownership, reviewed Receipt, fingerprint, Lease, Checkpoint,
  authority, Gate and transaction enforcement.
- Worker and Renderer receive no new Port, signing secret, database handle or
  filesystem capability.
- No Pivot IPC, Preload contract or Renderer surface was added.
- No installer or portable package was generated.

## Deliberately absent

- automatic child-Run `replan` continuation because no authoritative next
  Guarded Task is scheduled;
- self-repair/Fixer execution because assignment evidence is not Task
  scheduling evidence;
- non-Dry-run production failure sources;
- restart reconciliation UI or automatic replay of ambiguous work;
- restart-queryable Guarded completion/failure history;
- stop-driven external-process interruption;
- Human Escalation notification, queue, acknowledgement or resolution;
- Pivot IPC, Preload, Renderer or user-facing automatic repair workflow.

## Next recommended slice

Add an authoritative next-Task scheduling transition for child-Run `replan`,
then extend the reviewed-proposal orchestrator to that scheduled Task through
the same narrow Ports. Keep self-repair and dedicated-Fixer out until their
own Task scheduling transition exists. In parallel release planning, the
remaining v1.0 internal-beta path is approximately 2–3 integrated slices or
3–5 narrow slices: broader scheduling/history, unified-work completion, and
packaged upgrade/rollback/soak hardening.
