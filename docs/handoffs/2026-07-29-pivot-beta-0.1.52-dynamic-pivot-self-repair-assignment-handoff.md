# Pivot Beta-0.1.52 Dynamic Pivot self-repair assignment handoff

Date: 2026-07-29  
Visible version: `Beta-0.1.52`  
Package/updater SemVer: `0.1.52-beta`

## 1. Delivered engineering slice

Beta-0.1.52 establishes durable Worker identity and one non-executable same-Worker assignment for a decided minor `self-repair`.

1. `AxisWorkerAttemptBinding` records exact Run, Session, task, positive attempt, Worker, lifecycle revision and terminal evidence.
2. Reader, Lifecycle and Assignment capabilities are separate frozen Ports.
3. `AxisWorkerAttemptRegistry` persists attempt/assignment evidence in WAL-mode SQLite with unique task-attempt and decision constraints.
4. Self-repair input remains only decision, expected revision, Run and Session identifiers.
5. Task and issue come from the decided minor Pivot record; Worker comes from the latest failed attempt.
6. The Handler validates latest Pivot event, failed Run/task, decision snapshot/usage, attempt count and remaining retry/token/cost/duration/Gate budgets.
7. Sequential duplicate, matching concurrent conflict and database restart reuse one immutable assignment.
8. Assignment does not mutate Run state, invoke a Worker or grant execution/filesystem authority.

Worker and Renderer receive no Lifecycle/Admin Port, Registry, database handle, project root, filesystem, command, proof secret or execution authority.

## 2. Explicit non-delivery

- No production composition root constructs the Registry or Handler.
- No IPC, Preload, Renderer store or UI calls it.
- No scheduler consumes the assignment.
- No Run task is reopened and no retry budget is consumed by assignment.
- Same-Worker guarded execution still requires a separately reviewed scheduler/execution boundary.
- Dedicated Fixer, discard, stop and escalation handlers remain absent.

## 6. Remaining gap to Beta-1.0

The weighted estimate remains **about 93% complete**, with **about 7% remaining** and approximately **3–8 independent engineering slices**. This Main-only identity/assignment foundation reduces execution-policy risk but does not earn user-reachable release credit.

Highest-value remaining slices:

1. Production-compose `replan`, `retry`, and self-repair assignment behind a guarded scheduler/execution policy with real behavior tests.
2. Add dedicated Fixer, discard, stop and escalation handlers.
3. Add packaged release-process Renderer-to-Main E2E plus signing/update/rollback evidence.
4. Add restart-persistent Guarded completion/failure history and Blackboard evidence projection.
5. Add trusted project Gate profile discovery without accepting model/Renderer commands.
6. Finish release hygiene, degradation/circuit breaking, Gate 3 and representative soak/security validation.

The next bottom-layer slice should review guarded consumption of Dynamic Pivot actions or implement the remaining non-executing action boundaries. Production wiring must remain explicit because it changes reachability and execution policy.
