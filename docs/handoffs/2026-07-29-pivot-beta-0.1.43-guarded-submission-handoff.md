# Pivot Beta-0.1.43 guarded submission handoff

Date: 2026-07-29  
Visible version: `Beta-0.1.43`  
Package/updater SemVer: `0.1.43-beta`

## Delivered engineering slice

Beta-0.1.43 adds the first default-off, trusted-IPC primitive for production Axis Guarded Safe Write.

The shared request accepts only `runId`, `sessionId`, `taskId` and a bounded exact write set. Main resolves the authoritative Shadow task and persistent project binding, then calls a frozen execution-only Port. Renderer cannot submit a project root, task object, tool grant, authority envelope, proof material, Admin Port, database handle or filesystem adapter.

This is not yet a delivered end-user feature: no Renderer service, UI action, automatic Run workflow or completion/failure projection invokes the primitive.

## Files and boundaries

- `src/shared/axis-guarded-safe-write-contracts.ts`
  - strict request schema;
  - 1–16 unique paths;
  - 4 MiB aggregate content-character limit.
- `src/main/services/axis-guarded-safe-write-ports.ts`
  - execution-only Port;
  - persisted-task Reader Port.
- `src/main/services/axis-guarded-safe-write-submission.ts`
  - strict re-parse;
  - authoritative task/root resolution;
  - exact tool and assigned-file checks.
- `src/main/services/axis-shadow-run-registry.ts`
  - frozen task Reader Port.
- `src/main/services/axis-production-guarded-runtime.ts`
  - frozen execution Port preserving readiness, recovery and Blackboard initialization.
- `src/main/ipc-handlers.ts`
  - trusted `axis:execute-guarded-safe-write` handler;
  - default-off runtime remains controlled by strict `PIVOT_AXIS_REAL_EXECUTION=0|1`.

## Test-first evidence

The new tests failed before implementation because the shared schema, Ports, service, Reader Port and IPC channel did not exist.

After implementation:

- strict shared contract rejects forged authority fields, duplicates and oversized content;
- submission service fails closed for disabled runtime, missing ownership, unsafe tools and write-set drift;
- structural tests keep concrete registries, SQLite, Admin and filesystem capabilities out of the service, Worker and Renderer;
- real production adapters detect modified, deleted, created and same-content replaced files after Checkpoint and before Worker/transaction;
- each external-change case preserves external state, runs no Gate, creates no transaction and releases Leases.
