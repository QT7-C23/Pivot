# Pivot Beta-1.33.0 semantic Reviewer resilience handoff

Date: 2026-08-13  
Display version: `Beta-1.33.0`  
Package version: `1.33.0-beta`

## Delivered engineering slices

1. `Beta-1.29.0`: strict deterministic large-diff segment contracts and Main
   Segmenter.
2. `Beta-1.30.0`: segmented Reviewer aggregation with measured usage and
   fail-closed malformed-response handling.
3. `Beta-1.31.0`: post-write finding file/line validation against the exact
   snapshot.
4. `Beta-1.32.0`: independent primary/fallback Reviewer pool.
5. `Beta-1.33.0`: actual selected Reviewer identity propagation, durable audit
   attribution and production-composition failure-path coverage.

## Production activation contract

- `PIVOT_AXIS_SEMANTIC_REVIEW=1` remains required; semantic review is
  default-off.
- `PIVOT_AXIS_CORRECTNESS_REVIEW_MODEL` remains required.
- `PIVOT_AXIS_SECURITY_REVIEW_MODEL` remains optional and is needed for tasks
  that require the security Gate.
- `PIVOT_AXIS_CORRECTNESS_FALLBACK_REVIEW_MODEL` and
  `PIVOT_AXIS_SECURITY_FALLBACK_REVIEW_MODEL` optionally configure fallback
  Reviewers.
- Worker, correctness, security and fallback model identifiers must be pairwise
  independent. Configuration collisions fail before runtime construction.
- Every Reviewer remains Main-only and read-only. Renderer and Worker receive
  no Provider Store, Admin, database or filesystem capability.

## Behavioral guarantees

- Segments are deterministic, bounded, indexed contiguously and individually
  bound by SHA-256.
- Every segment response must satisfy the strict measured-response and proposal
  contracts. Any malformed segment invalidates the whole review.
- Aggregate review fails when any segment reports findings; confidence uses the
  minimum segment confidence and usage is summed.
- A fallback is attempted only after primary runtime failure. A primary
  `failed` proposal is a valid result and never triggers fallback shopping.
- If different segments resolve to different Reviewer identities, aggregation
  fails closed because the current evidence contract owns one actual Reviewer
  identity per review decision.
- Findings must target an exact after-write file and a real one-based line in
  that file. Invalid locations discard the proposal and route to human review.
- Durable decision and usage evidence use the actual selected Reviewer identity,
  including fallback selection.

## Important limits

- This is a default-off production capability, not a claim that semantic review
  is enabled for every user or Provider.
- There is no user-facing Reviewer status, fallback indicator, usage dashboard
  or review evidence browser yet.
- The current source mapping validates files and line bounds; it does not yet
  provide AST/symbol ownership, rename-aware mapping or column/range evidence.
- Provider-specific model existence/capability checks, restart/chaos campaigns
  and broad real-provider qualification remain.
- The external Obsidian product package was not changed in this slice set.

## Suggested next slice set

Build read-only operational telemetry and a user-reachable review evidence
surface, then add provider capability probes, restart/chaos qualification and
broader end-to-end release evidence without exposing privileged Main Ports.
