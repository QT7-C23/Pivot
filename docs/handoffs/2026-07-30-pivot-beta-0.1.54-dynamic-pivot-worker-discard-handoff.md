## 1. Delivered engineering slice

Beta-0.1.54 establishes one non-executable terminal disposition receipt for a decided `discard` action.

1. `AxisWorkerDiscardReceipt` strictly binds the decision, execution revision, reason, Run, Session, task, failed source attempt and source Worker.
2. Runtime validation rejects unknown fields, malformed identifiers and forged authority material.
3. The caller request remains four identifiers and cannot select the task, Worker, attempt, reason or capability.
4. `AxisWorkerDiscardPort` is a narrow frozen capability; the concrete Registry alone owns SQLite.
5. `AxisWorkerDiscardRegistry` persists one immutable receipt per decision in independent WAL-mode SQLite.
6. Registry creation revalidates the latest exact failed attempt through `AxisWorkerAttemptReaderPort`; malformed or mismatched Port output is rejected.
7. The Handler accepts only an unforced decided `excessive` discard bound to the latest failed Run/task/attempt and exact committed revision/snapshot/usage.
8. Exhausted continuation budgets do not block terminal disposition evidence because no further work is started.
9. Sequential repeat, matching concurrent conflict and database reopen reuse the same receipt without rebuilding work or mutating Run state.

Worker and Renderer receive no Worker lifecycle/Admin Port, Run mutation Port, Registry, database handle, project root, filesystem, signing secret or execution authority.

## 2. Explicit non-delivery

- No production composition root constructs the Registry or Handler.
- No IPC, Preload, Renderer service/store or UI calls it.
- No scheduler or Worker runtime consumes the receipt.
- No Run/task state or budget is changed.
- No Permission, Lease, Fingerprint, Checkpoint, signed authority or file write is performed.
- Stop semantics and human escalation action handlers remain absent.

This slice is terminal disposition evidence only. It is not a delivered discard feature and does not make Dynamic Pivot user-reachable.
