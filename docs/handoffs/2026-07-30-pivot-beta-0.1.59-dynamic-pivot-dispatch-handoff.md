# Pivot Beta-0.1.59 Dynamic Pivot dispatch handoff

Date: 2026-07-30  
Visible version: `Beta-0.1.59`  
Package/updater SemVer: `0.1.59-beta`

## Completed slice

- Added a strict four-field Dynamic Pivot dispatch request.
- Added one strict result envelope for all seven reviewed action results.
- Separated continuation actions from terminal evidence/state actions.
- Added generic narrow action executor Ports and one dispatcher Port.
- Added a Main dispatcher that derives its route only from the committed
  decision.
- Added a frozen composition function exposing only `dispatch`.
- Routed the real SQLite close/reopen stop integration through the dispatcher.

## Invariants preserved

- Caller input cannot choose the action or terminal/continuation route.
- Every action Handler retains ownership of its own authorization, state,
  idempotency, concurrency and persistence rules.
- The dispatcher revalidates decision ownership and post-decision revision
  before invoking exactly one action Port.
- Returned action evidence is strictly revalidated against decision, Run,
  Session, revision and route.
- Dispatcher and composition depend on Ports, not concrete action Handlers,
  Registries, database, filesystem, Worker or Execution Authority.
- Worker and Renderer receive no dispatcher or infrastructure capability.
