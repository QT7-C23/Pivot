# Pivot Beta-0.1.58 Dynamic Pivot stop handoff

Date: 2026-07-30  
Visible version: `Beta-0.1.58`  
Package/updater SemVer: `0.1.58-beta`

## Completed slice

- Added strict four-field Pivot stop request and decision-bound result.
- Added `pivot-stopped` as a strict lifecycle event.
- Preserved the historical planning-budget stopped invariant while allowing
  Pivot-stopped Runs to retain terminal task evidence.
- Added a pure stop transition that preserves completed/failed tasks and
  cancels pending/running tasks.
- Added a frozen `AxisPivotStopStatePort`.
- Added a Main-only Handler for model-selected and budget-forced stop decisions.
- Made sequential repeat, commit acknowledgement loss and SQLite reopen reuse
  the same terminal event without another revision.

## Invariants preserved

- `stop` does not consume another Pivot budget unit.
- Decision model usage remains accounted exactly once.
- The caller cannot choose task, reason, stop reason, forced state or authority.
- The Handler depends on Ports, not the concrete Run Registry.
- Worker and Renderer receive no state mutation, Admin, database, filesystem,
  command, Checkpoint, Lease, Fingerprint or Execution Authority capability.
- The Handler is outside production composition, IPC and UI.
