# Pivot Beta-0.1.44 guarded Run-state handoff

Date: 2026-07-29  
Visible version: `Beta-0.1.44`  
Package/updater SemVer: `0.1.44-beta`

## Delivered engineering slice

Beta-0.1.44 binds the default-off Guarded Safe Write submission primitive to explicit optimistic approval and authoritative durable Run state.

The shared request now requires a positive `expectedRevision`. After strict request, task, tool, assigned-file and project-binding checks, Main atomically claims the authoritative pending task through a narrow `AxisGuardedRunStatePort`. Stale approvals, unfinished dependencies and another running task fail before the execution Port can write.

Guarded completion, permission/Fingerprint block, rollback and unexpected execution failure are converted to strict `WorkerResult` evidence and committed to the authoritative task/Run state. Terminal Lease cleanup happens after the state commit, and cleanup failure remains visible without erasing the durable terminal state.

A typed Renderer service/store action submits the current Run revision and stores or reloads authoritative state. No UI control or automatic planner path calls this action, so this is still a bottom-layer workflow boundary rather than a delivered end-user feature.

## Test-first evidence

The new tests first failed on the absent revision field, Guarded state transitions, Registry methods, Lease-aware state Port and Renderer action.

After implementation:

- stale approval fails before execution;
- unfinished dependencies and concurrent running tasks cannot be claimed;
- completed and failed execution results produce strict lifecycle revisions;
- permission denial and timeout run no Checkpoint, transaction, Gate or write;
- compile-Gate failure physically restores the Checkpoint and releases the Lease;
- unexpected execution failure is durably projected before surfacing;
- cleanup failure is surfaced after the terminal state is durable;
- structural tests prohibit concrete Registry, SQLite, Admin and filesystem dependencies.
