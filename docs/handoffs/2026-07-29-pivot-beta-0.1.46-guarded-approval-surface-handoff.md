# Pivot Beta-0.1.46 guarded manual approval surface handoff

Date: 2026-07-29  
Visible version: `Beta-0.1.46`  
Package/updater SemVer: `0.1.46-beta`

## Delivered engineering slice

Beta-0.1.46 adds a default-off, user-reachable manual approval surface over the previously reviewed Guarded Safe Write boundary and proves its rollback path through a real production-build Electron process.

The surface is intentionally narrow:

- it appears only for pending Shadow tasks whose sole tool is `fs.safeWrite`;
- it accepts 1–16 authoritative assigned files;
- the user must enter complete replacement content for every file;
- the user must explicitly acknowledge the write and rollback risk;
- it submits only run/session/task identifiers, the current optimistic revision and the bounded write set.

The planner does not yet produce or hand off file content or patches. There is no automatic execution, diff-review handoff, successful completion evidence UI or packaged release-process E2E. This is a bottom-layer manual execution workflow, not a complete delivered autonomous write feature.

## Shared and Renderer boundary

- Added a strict read-only Guarded feature-state contract in `src/shared`.
- Added trusted IPC validation and a typed Renderer service/store query.
- Added the manual approval component and workspace placement without exposing Project Binding, Authority, proof material, Ports, database handles or filesystem capabilities.
- Moved the permission queue to `PivotAppShell`, so a Main-owned permission request remains actionable outside the Sessions tab.

## Main authority and composition fixes

The real Electron test exposed a production contract mismatch: Shadow Planning persists project-relative assigned files, while Permission, Checkpoint and Execution Authority previously required absolute paths.

Beta-0.1.46 resolves project-relative files only at those Main authority boundaries using the authoritative persistent Project Binding root. The existing canonical containment check still rejects traversal outside the root. Renderer input cannot provide or replace that root.

Structural tests also rejected concrete Guarded service construction inside `ipc-handlers.ts`. Concrete construction now lives in `src/main/services/axis-guarded-ipc-runtime.ts`. IPC handlers depend only on its narrow frozen runtime surface:

- `featureState`;
- `submit`;
- `ready`;
- `deleteForSession`;
- `close`.

Worker and Renderer still receive no Admin Port, Registry, SQLite handle, transaction journal, proof secret or raw filesystem adapter.

## Test-first evidence

The slice was developed through failing tests before implementation:

1. strict feature-state contract and IPC validation;
2. Renderer service/store state and failure behavior;
3. approval eligibility, complete-content collection and acknowledgement;
4. application-shell permission queue reachability;
5. real Electron Renderer → Preload → Main approval and rollback;
6. project-relative planner path normalization and traversal rejection;
7. structural rejection of concrete Guarded construction in IPC handlers;
8. dedicated Main composition-module ownership.

The real Electron E2E:

1. launches the production build with `PIVOT_AXIS_REAL_EXECUTION=1`;
2. creates an isolated project and Shadow Run through a local OpenAI-compatible endpoint;
3. fills the manual replacement content;
4. approves the Main-owned permission request;
5. triggers a deterministic TypeScript compile-Gate failure;
6. verifies the original file is physically restored.
