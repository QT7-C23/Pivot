# Pivot Beta-0.1.50 Dynamic Pivot replan action handoff

Date: 2026-07-29

Package/updater SemVer: `0.1.50-beta`

## 1. Delivered engineering slice

Beta-0.1.50 connects only a durably decided Dynamic Pivot `replan` outcome to the existing revision-bound Provider replay boundary.

1. `src/shared/axis-pivot-action-contracts.ts` defines strict request and result contracts.
2. Caller input contains only decision, expected revision, Run and Session identifiers.
3. `axis-pivot-action-ports.ts` defines narrow decision-reader, Run-state-reader, planning-context, project-file-list and replan capabilities.
4. The Main handler revalidates:
   - `decided` and unforced `replan`;
   - exact Run/Session ownership;
   - exact post-decision optimistic revision;
   - source objective and budget snapshot;
   - authoritative usage including Pivot Provider usage;
   - the latest matching `pivot-decided` lifecycle event.
5. The child budget is derived only from the parent's remaining limits.
6. The planning-context adapter resolves the canonical project binding and frozen file manifest in Main. Caller input cannot choose a root, files, commands or Provider configuration.
7. A completed lineage is reused idempotently without a second Provider call or duplicate child. A failed, stale, interrupted or active same-source attempt blocks automatic replay until a new Pivot revision and decision.
8. Revision-bound replanning now accepts a paused parent in addition to failed and budget-stopped parents.

Worker and Renderer receive no Admin Port, Registry, database handle, project root or filesystem capability.

## 2. Explicit non-delivery

- The handler is not constructed by production composition.
- There is no IPC channel, preload contract, Renderer store or UI entry point.
- A materialized child plan is planning evidence, not automatic execution.
- Self-repair, retry, dedicated Fixer, discard, stop and escalation action boundaries remain absent.
- The default-off Guarded Safe Write production chain is unchanged.

## 3. Tests added or strengthened

- Completed-lineage idempotency without a second Provider invocation.
- Failed same-revision replay rejection.
