## Delivered engineering slice

This slice delivers Figma New Project `597:5842`, No Projects `597:6165`, No
Automations `597:6278`, and No Extensions `597:6403` as production-reachable
interfaces. Docs was explicitly deferred and is not claimed.

- `src/shared/project-creation.ts` strictly validates the immutable creation
  request/result. It rejects reserved or unsafe project names, invalid parent
  paths, non-HTTPS origins and origins without Git initialization.
- `ProjectCreationPort` is the narrow Main boundary. The Node Adapter verifies
  the canonical parent, refuses existing targets, executes Git without a
  shell, and rolls back only the newly created target after any failure.
- Renderer calls the validated `project:create` IPC through `projectService`;
  it receives no filesystem handle, command runner, database handle, Admin
  Port or execution authority.
- Successful creation authorizes the new project, opens the existing Session
  path, selects the requested real runtime profile and reaches Conversation.
- Project creation and import are real actions. Automation creation is visibly
  disabled because no Scheduler runtime exists. Automation templates and the
  empty installed-extension inventory navigate to the existing Marketplace.
- Figma demonstration extensions, recommendations, ratings, installs and
  automation runs are not inserted.
- New route surfaces are lazy-loaded so the unchanged performance gate remains
  enforced.
