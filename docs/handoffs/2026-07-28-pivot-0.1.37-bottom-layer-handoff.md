## 下一阶段工作

按下面顺序小步推进，每步先写真实能力测试：

1. 使用 CodeGraph 审查 `axis-guarded-safe-write`、`file-checkpoints`、`safe-file-writer`、Execution Authority 和现有 File Identity/Lease 的调用关系与影响范围。
2. 定义 External File Fingerprint Evidence 的共享合同。它需要区分存在文件和缺失目标，使用内容级摘要而不是只信任 mtime，并与 project/file identity 绑定。
3. 定义最小读取/验证 Port。文件系统读取只能位于 Main Adapter；Worker 只能提交目标并接收不可伪造的验证结果，不能获得文件系统或 Admin 服务。
4. 先建立失败基线，覆盖文件在 Lease/Checkpoint 后被外部修改、删除、创建或替换时拒绝写入。
5. 实现 Fingerprint Adapter，并验证路径边界、malformed input、所有权、陈旧证据和失败路径。
6. 单独复审通过后，再设计 Guarded Safe Write 协调器，将顺序固定为：
   - acquireAll；
   - capture fingerprint；
   - create checkpoints；
   - bind Lease ID/Version + fingerprint evidence into authority；
   - mutation 前再次 verify；
   - guarded write；
   - completion/failure/cancel/rollback 的 finally 路径 releaseAll。
7. 生产接线必须有真实行为测试，不能只断言类型、源码字符串或 mock 非空。
8. 完成后运行定向测试、全量测试、TypeScript build、正式构建、性能门禁和 Electron 原生依赖验证。
9. 完成一个独立切片后升级到 `0.1.38`，同步工程文档和产品策划包。
